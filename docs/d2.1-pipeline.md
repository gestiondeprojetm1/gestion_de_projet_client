# D2.1 — Pipeline préparé

Le workflow `.github/workflows/ci.yml` conserve les contrôles obligatoires des Pull Requests : tests pytest, scan Gitleaks et build Docker sans publication.

Sur un tag SemVer `vX.Y.Z`, il publie l'image sur GHCR avec `packages: write` et génère l'artefact `deployment.env`. Ce manifeste contient l'image validée sous forme de digest immuable, la version, le SHA Git et le chemin `/health`.

Le job `deploy-staging` réutilise ce digest, démarre un PostgreSQL isolé et le conteneur API sur le runner GitHub, rejoue la migration, puis vérifie `/health` avant et après migration. Il utilise l'environnement GitHub `staging`, jamais les secrets de production, et nettoie les conteneurs en fin de job.

Ce manifeste est transmis à D2.2. Le même digest devra être utilisé en staging puis en production. Aucun serveur, secret de déploiement ou déploiement réel n'est configuré dans D2.1.

La protection GitHub devra encore être configurée avec les environnements `staging` et `production`, ce dernier ayant une règle de reviewers requis. Les secrets d'infrastructure attendus sont propres à l'environnement et ne doivent pas être exposés aux workflows de Pull Request.

Le smoke test réutilisable se trouve dans `scripts/deploy/smoke_test.ps1` et la procédure de rollback par digest dans `docs/releases/rollback.md`. Leur exécution réelle dépend de l'infrastructure que D2.2 doit configurer.
