# Fiche de mise en production — v1.0.0

## 1. Informations générales

- **Version :** v1.0.0
- **Type de livraison :** Version initiale
- **Fonctionnalité :** Gestion du stock des produits
- **Environnement cible :** Production
- **Responsable du déploiement :** Équipe DevOps
- **Approbateur :** Product Owner / responsable désigné de l'équipe (à confirmer)

## 2. Contenu de la livraison

Cette version introduit la gestion du stock des produits.

- Déclaration du stock disponible pour chaque produit.
- Vérification du stock avant validation d'une commande.
- Refus d'une commande lorsque la quantité demandée dépasse le stock disponible.
- Affichage d'un message d'erreur clair en cas de stock insuffisant.

## 3. Risques identifiés

| Risque | Mesure préventive |
|---|---|
| Stock incorrect après une commande | Tester la mise à jour du stock |
| Commande acceptée malgré un stock insuffisant | Ajouter des tests de validation |
| Indisponibilité de l'API après déploiement | Effectuer un test de santé |
| Problème de connexion à PostgreSQL | Vérifier la connexion à la base de données |

## 4. Critères Go / No-Go

### GO
- Tous les tests passent.
- L'image Docker est construite correctement.
- L'API répond sur `/health`.
- La connexion à PostgreSQL fonctionne.
- Le test de gestion du stock est validé.
- L'approbation du responsable est obtenue.

### NO-GO
- Un test critique échoue.
- L'API ne répond pas.
- La base de données est inaccessible.
- La gestion du stock présente une anomalie.
- L'approbation n'est pas obtenue.

## 5. Plan de retour arrière (Rollback)

En cas d'échec après le déploiement :

1. Arrêter la nouvelle version.
2. Redéployer l'image Docker de la version précédente.
3. Vérifier que l'API répond sur `/health`.
4. Vérifier la connexion à PostgreSQL.
5. Confirmer le retour au fonctionnement normal.

**Objectif :** effectuer le rollback en moins de 5 minutes.

**Limite :** le retour à l'ancienne image ne garantit pas l'annulation des modifications déjà effectuées dans la base de données.

## 6. Validation et approbation

- **Responsable du déploiement :** Équipe DevOps.
- **Approbateur :** À confirmer par l'équipe.
- **Décision :** GO / NO-GO.
- **Date de déploiement :** À renseigner.
