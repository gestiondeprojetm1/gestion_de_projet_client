# D2.1 — Découpage de la réalisation

Chaque membre travaille sur sa propre branche et publie ses propres commits. Aucun commit ne doit être fabriqué au nom d'un autre membre.

| Membre | Branche | Fichiers principaux | Dépendances | Validation |
|---|---|---|---|---|
| 1 — Modèle | `feature/stock-modele` | `app/models.py`, `migrations/001_add_stock.sql` | Socle API fusionné | Migration sur une base existante, stock non négatif |
| 2 — Déclaration | `feature/stock-declaration` | `app/schemas.py`, `app/main.py` | Modèle du membre 1 | PUT stock, produit absent, valeurs invalides |
| 3 — Commandes | `feature/stock-commandes` | `app/main.py` | Modèle du membre 1 | 201 si stock suffisant, 409 sinon, décrémentation |
| 4 — Tests | `test/stock-api-concurrence` | `tests/` | Fonctionnalités 1 à 3 | Tests API et test PostgreSQL concurrent |
| 5 — CI/GHCR | `feature/pipeline-stock` | `.github/workflows/ci.yml`, `docs/pipeline.md` | Tests validés | Tests, secrets, build, publication taguée |
| 6 — Préparation exploitation | `feature/preparation-deploiement-stock` | `scripts/deploy/`, `docs/releases/` | Image GHCR et CI | Smoke test, variables documentées, rollback prêt |

La branche personnelle de l'auteur de D2.1 regroupe uniquement les changements qu'il réalise réellement. Les autres contributions doivent être faites et commitées par leurs auteurs.

Les contributions des cinq autres membres restent à réaliser par eux-mêmes sur les branches indiquées. Ce document ne constitue pas une preuve de commits : l'historique Git et les Pull Requests de chaque auteur devront servir de preuve.
